# 已知限制

- 单个逻辑消费者、至少一次交付；没有跨进程任务领取租约。附件锁只保护同一目标文件。
- 机器人附件每请求一块仍重新完整下载和解密原文件。大文件会放大流量及耗时，计划改进，当前不建议依赖此路径传输重要大附件。
- 机器人客户端单次超时 12 秒，而 Worker 上游请求超时 20 秒；协调超时尚待修订。120 秒重试预算不是严格的进程总耗时保证。
- 机器人附件链接可能很快过期；明确过期才设 needs_resend，其他故障不能误标过期。回复窗口也有限，存入回复不等于用户收到。
- 客服 SQLite 使用服务 URL 绑定部署身份；直接换域名会拒绝复用原状态。后续需要显式迁移工具，不能删库绕过。
- D1 正文、ACK、附件元数据及客服 SQLite 没有自动清理策略。不要直接删除去重历史，否则旧回调可能重新成为任务。
- `/health` 不查询数据库，不验证外部 API；尚无积压监控和告警。
- 没有公开互联网多租户管理界面、分用户 API 凭证或全局发送幂等账本。
- 应用出向素材支持图片/文件；行内上传 2 MiB，允许来源 URL 文件最大 20 MiB；机器人下载最大 8 MiB。实际平台规则仍需在测试企业验收。
- 当前开源基线通过本地模拟测试，不等于已完成新环境端到端验收。更完整的英文部署文档仍在计划中。
